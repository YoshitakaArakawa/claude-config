# Reviewing Videos

作り手は素材を読み込んでいるので、素材への引きずりや説明不足に気づけない。自己レビューで済ませず、文脈を持たない視聴者役と、出典だけを見る照合役に分けてレビューさせる。

## 規範

- **2 役は 1 つのメッセージで並列に起動する**。互いの結果を見せない
- **視聴者役に文脈を渡さない**。制作の経緯・意図・出典のパスを書かない。渡すのはレビュー素材のフォルダだけ
- **書き換え案をそのまま使わない**。レビュアーの案にも、根拠のない数字や事実が混ざる。指摘は採用してよいが、案の中身は出典と照合してから使う
- **重い指摘は実ファイルで裏取りしてから直す**。照合役の「出典にない」「逆である」という指摘は、作り手が該当箇所を開いて確かめる

## 手順

```
進捗：
- [ ] 1. レビュー素材を作る
- [ ] 2. 出典の一覧を作る
- [ ] 3. 2 役を並列で起動する
- [ ] 4. 指摘を裏取りして仕分ける
- [ ] 5. ユーザーに反映方針を出す
```

### 1. レビュー素材を作る

版ごとに別のフォルダへ書き出す（前回の素材と混ぜない）。

```bash
node ${CLAUDE_PLUGIN_ROOT}/scripts/capture.cjs scene.html review/vN
```

次の 3 つができる。前提（Node・Playwright）は making-videos と同じ。

- `frames/fNNN.jpg`：1.5 秒ごとの原寸フレーム（`--every` で間隔を変える）
- `sheetN.png`：フレームを 3×3 に並べ、時刻ラベルを付けたコンタクトシート
- `onscreen-text.md`：場面ごとの画面上の文字と表示秒数

### 2. 出典の一覧を作る

照合役に渡すファイルを列挙し、それぞれの役割を 1 行で添える。

- 作業ログ・会話の記録（誰が何を言い、何をしたかの一次情報）
- 各版の成果物（数字を数え直す対象）
- 元にした資料（図・アーティファクト。引きずりの照合に使う）
- `scene.html` とレビュー素材の `onscreen-text.md`

何が出典か分からないときは、ユーザーに 1 問だけ聞く。

### 3. 2 役を並列で起動する

Agent ツールを 1 つのメッセージで 2 回呼ぶ。プロンプトは雛形の `<...>` を埋めて渡す。

| 役 | 雛形 | model | 見てよいもの |
|---|---|---|---|
| 初見の視聴者 | [references/viewer-prompt.md](references/viewer-prompt.md) | `fable`（使えなければ `opus`） | レビュー素材のフォルダだけ |
| 出典の照合 | [references/source-check-prompt.md](references/source-check-prompt.md) | `opus` | 動画の文字・HTML と出典の一覧 |

### 4. 指摘を裏取りして仕分ける

2 役の指摘を 1 つの表にまとめ、各行を次のどれかに仕分ける。

- **採用**：裏取りできた、または表現の問題で裏取りが要らない
- **案を差し替えて採用**：指摘は正しいが、書き換え案に出典の無い事実が入っている。出典から書き直す
- **見送り**：出典と照合して誤りだった、または意図した表現。理由を書く
- **要確認**：出典だけでは決められない（ユーザーの記憶や判断が要る）

照合役の重い指摘は、該当する出典ファイルを開いて確かめてから仕分ける。数字の指摘は実ファイルから数え直す。

### 5. ユーザーに反映方針を出す

最大の弱点を先頭に 1 つ書き、次に仕分けた表を出す。要確認の項目があれば、末尾で 1 問にまとめて聞く。反映は making-videos の手順で、版を残してから行う。直した版は新しい素材で再レビューする。視聴者役は毎回新しく起動し、前回の指摘を渡さない。
